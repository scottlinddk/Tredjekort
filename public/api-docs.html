Map data by address

A public, read-only JSON API for the 3. Limfjordsforbindelse map. Look up a Danish address to get a prose description, distances, nearby map features and the official project sources. No API key required.

Expected road noise with the motorway. noise.expectedWithProject first uses official model values for matched dwelling records, then the original proposal's contour band. These are results from the 2021 model for 2040, including the motorway and selected surrounding roads. They are not current measurements, the motorway's isolated contribution or the latest 2035 design. Existing noise.ldenDb, audibility and compliance fields remain null.

Try a report

Request

GET /api/address-report?address=N%C3%B8rholmsvej%20180%2C%209000%20Aalborg&lang=da

Send exactly one of address (3–200 characters) or id (a DAWA access-address UUID). lang is da by default; en is also supported. Use an access address without floor or door. The address field uses DAWA search without fuzzy matching.

For an address chosen on the map or returned by /api/addresses?q=..., use its ID:

GET /api/address-report?id=<DAWA-access-address-UUID>&lang=en

What the response contains

  • address: resolved name, ID, WGS84 coordinates and DAWA source URL.
  • description: prose in the requested language.
  • noise.expectedWithProject: the original proposal's expected noise as a modeled dwelling value, a min/max across all matched dwelling records, or an official contour band. Its description leads the main report.
  • proximity: nearest approximate motorway segment and junction, plus local roads and noise-barrier sections within 2,000 metres. These line features retain GeoJSON geometry and source properties. nearestOfficialDesign separately gives distance to the official 2025 design centreline network, including ramps and local roads; its large geometry is omitted.
  • noise.legacyModel: official 2021 model bands for the 2040 original, reference and variant scenarios, with source IDs, dates and lookup status. noise.current2035 explicitly marks address-level contours unavailable for the current PDF material.
  • landRequirements: whether the address point falls inside or on a boundary of official 2025 permanent or temporary land requirements. Source properties are included, without the large polygons. A known invalid polygon component gives source_geometry_invalid only within that component's bounding box; inspect sourceGeometryIssues. This does not establish expropriation or the position of a property boundary.
  • projectInformation: shared project facts, timeline, updates and documents from the web app, with bilingual text.
  • provenance and limitations: review date, sources and explicit limits of the data.

Distances are geodesic distances to the approximate map geometry, rounded to 10 metres. Positions may differ by several hundred metres. The 2 km filter is a proximity filter, not an impact boundary. A nearby barrier does not establish noise protection. Barrier lengths may describe groups; do not sum them without checking the source.

Reading the expected with-project result

For status: point_value_found, valueDb is the source's modeled dwelling/facade value. For point_range_found, read receiverRange.minDb and maxDb. receiverRange is present for both statuses and includes receiverCount; a single or identical value has equal minimum and maximum. Numeric fields retain the published decimals; display one decimal place. Source precision is not measured accuracy.

Receiver matching requires DAWA municipality 0851, road code and house number, plus a distance of no more than 50 metres between the keyed historical record and current address point. Formatting differences such as leading zeros and house-letter case are normalized. This guard never selects a nearest address. All matched dwelling rows are included; raw floor codes are preserved without interpreting their labels.

Zero sentinels and missing model values are unknown. If any matched dwelling lacks an original-scenario value, the API does not present a partial min/max as complete. It falls back to the original contour if usable. receiverDataStatus explains the receiver lookup. The reference and variant are never substitutes for the original proposal.

For band_found, read band; its midpoint is never used as a point value. Boundary, overlap, invalid-geometry and unmapped results keep the band and numeric value null. The top category remains 78 dB with an unspecified upper bound. A missing contour does not mean below 53 dB; a safely matched receiver can have a published value below that contour threshold.

exactDb is null because an exact actual or measured sound level is unsupported. motorwayOnlyDb is null because this model does not isolate the motorway from selected surrounding roads. This additive result preserves the existing response schemaVersion: 1.0 and historic scenario fields.

Reading noise bands

Each legacy scenario returns band: { lowerDb, upperDb, label } only for a clear match. The model indicator is Lden and the units are dB(A). The top source category is labelled 78 dB; its upper bound is unknown (null). The original model uses Nord2000 / SoundPLAN 8.1, a 10 × 10 metre calculation grid and a height of 1.5 metres. It includes the motorway and selected crossing and surrounding roads; some roads are excluded. These bands represent neither the motorway's isolated contribution nor complete exposure from every road. Do not subtract bands to invent an exact noise change.

  • band_found: one unambiguous published band.
  • no_matching_contour: no available band at the point; this does not establish noise below 53 dB or the absence of noise.
  • boundary or overlapping_bands: band is null; inspect candidateBands.
  • source_geometry_invalid: the point is in the bounding box of a known self-intersecting source polygon component. No definitive band is given; affected feature IDs appear in sourceGeometryIssueFeatureIds. Valid components of the same feature remain queryable elsewhere.

The API uses unsimplified source polygons. The map uses a display copy simplified by approximately one metre, so a visual edge can differ slightly. These are model bands, not measured or exact address-level sound values.

Errors

StatusMeaning
400Missing, duplicate or invalid query parameters.
404No matching access address.
405Unsupported method. Use GET; OPTIONS supports CORS.
409Ambiguous address. Choose one of error.candidates and repeat with its id. At most ten candidates are returned; moreCandidates indicates more matches.
500The local map dataset could not be read or the report could not be generated.
502 / 504Address service unavailable, invalid response or timeout. Retry later.

Errors use { "error": { "code": "…", "message": "…" } }. Messages are in English; successful descriptions support Danish and English. Responses use Cache-Control: no-store and allow cross-origin reads.

Integration

const query = new URLSearchParams({
  address: 'Nørholmsvej 180, 9000 Aalborg',
  lang: 'en'
})
const response = await fetch(`/api/address-report?${query}`)
const report = await response.json()
if (!response.ok) throw new Error(report.error.message)
console.log(report.description)

The endpoint runs on Vercel, in local development and in the local preview server. A static-only hosting service cannot execute the API.
